# 관리자 페이지

- 주소: `/#/home/admin` 또는 `/admin.html` (같은 사이트의 별도 HTML 문서).
- 기존 회원 로그인과 동일한 HttpOnly 쿠키를 사용합니다.
- Supabase Auth의 `app_metadata.ieatbusan_admin === true`인 계정만 관리 API를 사용할 수 있습니다. 2026-11-10에 사용자 요청으로 `fnancier` 계정에 적용했습니다. 비밀번호는 변경하지 않았습니다.
- 여러 계정을 지원합니다. 권한은 신뢰할 수 있는 서버/DB 관리자만 변경해야 합니다. `user_metadata`나 프로필을 수정해서 관리자 권한을 얻을 수는 없습니다.
- 관리 API는 매 요청마다 Auth `/user`로 계정을 확인한 뒤, 서버에만 있는 Supabase secret을 사용합니다. 브라우저에는 secret과 인증 토큰을 전달하지 않습니다. 일반 회원의 기존 RLS 규칙은 변경하지 않습니다.

## 관리 범위

- 음식: 이름, 설명, 분류, 이미지 파일 이름, 기존 상세 문구를 수정합니다. 삭제는 `content.catalogStatus = archived`로 숨기며 복원할 수 있습니다.
- 식당: 이름, 주소, 영업시간, 휴무일, 전화번호, 이미지 파일 이름을 수정합니다. 기존 음식 연결을 보존하기 위해 삭제 기능은 제공하지 않습니다.
- 커뮤니티 게시글: 제목과 내용을 수정하거나 게시글을 삭제합니다. 삭제하면 DB 외래키 규칙에 따라 해당 댓글도 삭제됩니다.
- 댓글: 내용을 수정하거나 삭제합니다.
- 식당 이미지는 기존 `assets/restaurant/`, 음식 이미지는 `assets/food/`의 파일 이름을 사용합니다. 새 파일 업로드 기능은 포함하지 않습니다.
- 음식 상세 문구의 HTML 서식은 유지하고 문장만 편집합니다. 언어별 문구는 각각 수정합니다. 새로운 문장의 자동 번역은 수행하지 않습니다.
- 저장은 Supabase에 즉시 반영됩니다. 공개 화면을 새로고침하면 최신 내용을 읽습니다. 파일에 고정된 공통 메뉴/버튼 문구는 관리 대상이 아닙니다.
- `updated_at` 또는 원래 내용으로 동시 수정 충돌을 검출하며, 최신 변경을 덮어쓰지 않고 다시 불러오도록 안내합니다.

## 실행과 검증

`node tools/dev-server.cjs`로 실행 후 `http://127.0.0.1:8779/#/home/admin`에 접속합니다. 실제 로그인/저장에는 기존 Supabase 환경변수 설정이 필요합니다.

`node tests/admin-api.cjs`는 실제 회원 데이터를 바꾸지 않고 권한, 위조 방지, 수정, 삭제, 복원, 동시 수정 충돌을 검증합니다. `node tests/admin-browser.cjs`는 별도 포트 8782에서 가상 관리자 데이터로 화면을 확인하는 서버이며 실제 Supabase에 연결하지 않습니다.

`node tools/build-static.cjs`는 `admin.html`을 배포 폴더에 포함합니다. 배포 전에는 운영 도메인에 새 관리 페이지가 나타나지 않습니다.
