# GA4 KPI 연결

- 측정 ID: `G-8S5WRPX8S9`
- 운영 도메인: `https://ieatbusan-eight.vercel.app/`
- 구현일: 2026-11-06
- 로컬·Vercel 미리보기 주소는 수집하지 않습니다. 운영 도메인이 바뀌면 `js/analytics.js`의 도메인도 바꿉니다.

## GA4 관리 화면에서 필요한 설정

1. 관리 → 데이터 스트림 → 웹 스트림 → 향상된 측정의 설정 → 페이지 조회의 고급 설정에서 **브라우저 방문 기록 이벤트에 따른 페이지 변경**을 끕니다. 앱이 화면 이동을 직접 측정하므로 이 설정을 켜 두면 조회가 중복될 수 있습니다. 코드의 `send_page_view: false`만으로는 이 옵션을 끌 수 없습니다.
2. 향상된 측정의 **사이트 검색**과 **양식 상호작용**도 끕니다. 이 서비스의 검색·회원가입은 아래 직접 측정으로 관리합니다. 검색어·계정 입력값을 추가 수집하지 않습니다.
3. 관리 → 맞춤 정의 → 맞춤 측정기준 만들기에서 아래 항목을 **이벤트 범위**로 등록합니다.

| 표시 이름 | 이벤트 매개변수 | 용도 |
|---|---|---|
| 로그인 상태 | `login_status` | `logged_in` / `guest` |
| 화면 종류 | `page_type` | `home`, `community`, `post` 등 |
| 게시물 ID | `post_id` | 게시물별 조회·이용자 비교 |
| 게시물 분류 | `post_category` | 게시물 카테고리 비교 |

4. 필요하면 `sign_up`을 주요 이벤트로 표시합니다. 단순 조회를 주요 이벤트로 지정하지 않습니다.
5. 실시간 보고서에서 수신을 확인합니다. 맞춤 측정기준을 일반 보고서/탐색에서 쓰기까지 24~48시간이 걸릴 수 있습니다. 과거 방문을 소급 수집하지 않습니다.

## 수집 정의

| 이벤트 | 발생 시점 | KPI |
|---|---|---|
| `page_view` | 인증 초기화 후 화면을 표시했을 때 | 페이지별 조회수·이용자 수 |
| `post_view` | 존재하는 게시물 상세를 표시했을 때 | 게시물별 조회수·이용자 수 |
| `login` | 로그인 성공 후 서버 계정 정보를 불러왔을 때 | 로그인 완료 횟수 |
| `sign_up` | 회원가입 API 성공 시 | 회원가입 완료 횟수 |
| `logout` | 로그아웃 완료 시 | 로그아웃 횟수 |

각 이벤트에 해당 시점의 `login_status`를 전송합니다. 기존 로그인 세션을 복원한 방문자는 첫 조회부터 `logged_in`이며 새 `login` 이벤트를 만들지 않습니다. 인증 정보 조회 실패 시 로그인 상태를 임의로 추측하지 않고 초기 조회를 보류합니다.

게시물 ID·분류를 제외한 제목, 본문, 댓글, 검색어, 아이디, 닉네임, 비밀번호는 직접 전송하지 않습니다. GA4 User-ID에는 서버에서 확인한 내부 계정 UUID만 사용하며 로그아웃/탈퇴 후 즉시 `null`로 해제합니다. UUID를 맞춤 측정기준으로 등록하지 않습니다.

해시 URL은 보고용 가상 경로(`/home`, `/post/게시물ID`, `/results/분류`)로 전환합니다. 검색어와 URL 쿼리는 제거하고 화면 제목은 고정된 이름을 사용합니다. 가상 경로는 보고서용이며 웹사이트의 실제 새 주소가 아닙니다.

좋아요·댓글·정렬·언어 변경이나 같은 화면의 새로 그리기는 추가 조회로 세지 않습니다. 다른 화면에 갔다가 돌아오거나 브라우저를 새로고침하면 새 조회로 집계합니다. 없는 게시물은 `post_view`에서 제외합니다.

## KPI 탐색 보고서 만들기

GA4 → 탐색 → 자유 형식에서 아래 두 개를 만듭니다.

1. **로그인 상태별 페이지 이용**: 행에 `로그인 상태`, `페이지 경로 및 화면 클래스`; 값에 `총 사용자`, `조회수`; 필터 `이벤트 이름 = page_view`.
2. **게시물 조회 순위**: 행에 `게시물 ID`, `로그인 상태`(필요 시 `게시물 분류`); 값에 `이벤트 수`, `총 사용자`; 필터 `이벤트 이름 = post_view`.

전체 이용자 수는 `총 사용자`, 로그인 완료 횟수는 `login` 이벤트 수로 봅니다. 같은 사람이 비로그인 상태로 둘러보다 로그인하면 두 상태의 사용자 수에 모두 포함될 수 있으므로 두 값을 단순 합산하지 않습니다. `page_view`와 `post_view`는 같은 게시물 방문에 함께 발생하므로 두 이벤트 수를 더해 페이지 조회수로 사용하지 않습니다.

GA4는 태그·네트워크·브라우저 차단의 영향을 받습니다. 서비스 DB의 게시물 조회수 표시나 정확한 회원 수를 대체하지 않으며 서버 데이터는 이번 작업에서 변경하지 않습니다.

## 검증

`node tests/analytics.cjs`, `node tests/auth-regressions.cjs`, `node tests/public-entry.cjs`, 정적 빌드와 배포 검사를 실행합니다. 분석 테스트는 실제 Google 요청을 보내지 않는 격리된 환경입니다. 실제 수신 여부는 GA4 실시간/DebugView에서 별도 확인합니다.
