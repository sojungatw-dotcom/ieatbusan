# 챗봇 하단 스크롤 여유와 모바일 브라우저 표시

2026-11-16 / 기준 main 0df7ed1 / 브랜치 fix/chatbot-scroll-clearance

작업 전에 최신 main을 fast-forward로 반영했습니다. 이전 조건 카드 변경과 새 모바일 인트로를 보존했습니다.

## 재현한 문제와 변경

390×844 화면의 언어 선택 페이지에서 끝까지 스크롤해도 확인 버튼 영역이 챗봇 실행 버튼과 겹쳤습니다. 사용자 요청에 맞춰 하단 콘텐츠 뒤에 챗봇 아이콘 높이만큼의 비상호작용 공간을 추가했습니다. 모바일(740px 이하)은 56px, 나머지는 60px입니다. 아이콘 크기와 여유 공간이 같은 CSS 변수를 사용합니다. 기존 탭바·고정 CTA·댓글 입력창의 여유 패딩은 그대로 유지됩니다. 모바일 지도 개요는 문서 끝에, 데스크톱 지도 개요 및 상세는 내부 결과 목록 끝에 여유를 두고 지도 자체의 고정 높이는 바꾸지 않습니다.

이전 96px 여유 검증 후 사용자가 아이콘 높이만큼만 추가하도록 요청하여 56/60px로 줄였습니다. 아래 42개 화면 조합 검증 기록은 96px 당시의 기록이며, 최종 크기 검증은 icon-height-checks.json을 참조합니다.

## 브라우저별 축소 신고

사용자 보고: Chrome에서는 정상이나 네이버 앱 등 일부 브라우저에서 글자·버튼·아이콘 등 화면 전체가 작아짐. 특정 기종에 국한되지 않음.

메인과 챗봇의 viewport에는 이미 device-width와 initial-scale=1이 설정되어 있었습니다. Chrome 기반 브라우저 검사에서 해당 전체 축소 현상은 재현되지 않았고, 여러 페이지의 가로 넘침도 확인되지 않았습니다. 따라서 네이버 앱 내부의 정확한 원인은 확정하지 않았습니다.

WebKit의 자동 축소 방지 옵션 `shrink-to-fit=no`를 두 진입 문서에 명시하고, 두 문서의 글자 크기 자동 조정 기준을 100%로 통일했습니다. 관련 캐시 버전도 변경했습니다. 확대 제스처를 막는 maximum-scale이나 user-scalable=no는 추가하지 않았습니다. 이 변경은 호환성 보완이며 네이버 앱의 실제 문제 해결을 검증했다는 의미가 아닙니다.

근거: [Apple WWDC19 viewport 설명](https://developer.apple.com/videos/play/wwdc2019/203/)의 자동 축소 및 shrink-to-fit 설명. 이를 네이버 앱의 확정 원인으로 간주하지 않습니다.

## 검증

- Chrome 기반 브라우저에서 320·360·390·430·768·1280px × 홈·육류 목록·음식 상세·지도 개요·커뮤니티·마이·언어: 42개 조합에서 문서 가로 넘침 없음.
- 이전 96px 검증 당시 각 폭의 언어 페이지에서 확인 영역과 아이콘의 간격을 검사했습니다.
- 데스크톱 지도는 문서 여유 박스를 제거하고 내부 음식 목록에 같은 아이콘 높이의 여유를 적용합니다.
- 390px 챗봇 iframe의 clientWidth/scrollWidth 모두 390px이며 언어와 새 viewport 설정 유지.
- 배포 검사는 먼저 빌드해야 하므로 새 정적 빌드 후 재실행하여 통과. 전체 독립 실행 테스트 44개 통과.
- 테스트 데이터 서버(8783)에서 화면 검사, 운영 DB 쓰기 없음. 실제 iOS·Android 네이버 앱 및 설치형 앱은 미검증. 운영 배포하지 않음.
