# 회원 국가 기능 — DB 구조 대조 완료·적용 대기

2026-11-05, 브랜치 `feature/member-country`. 사용자 승인으로 기능 보관용 브랜치에 커밋·푸시합니다.
**DB 적용·실제 계정 검증 전에는 main에 병합하지 않습니다.** 운영 DB 변경은 수행하지 않았습니다.

## 제공된 DB 구조 대조

사용자가 제공한 `../조사자료/IEATBUSAN_Supabase_테이블구조_20261105.xlsx`(2026-11-05 조회본)의
6개 시트를 검토했습니다. 원본 엑셀은 수정하지 않았으며 DB에 직접 접속한 검사는 아닙니다.

- `컬럼정의!A7:H38`: 6개 앱 테이블/32개 컬럼의 이름·순서가 저장소 schema.sql과 일치.
  회원은 6개 컬럼, 게시글은 11개 컬럼이며 현재 country_code는 없음.
- `관계와제약!A11:E13`: 게시글 작성자 FK 이름과 프로필→Auth 연결이 서버 쿼리와 일치.
- `접근정책!A7:G23`: 저장소와 동일한 17개 RLS 정책 확인. 본인 프로필 수정/본인 글 작성 정책 유지 가능.
- `접근정책!A30:D33`: authenticated는 프로필의 area/bio/nickname 수정만, 게시글은 기존 7개 컬럼 삽입만 허용.
  준비한 SQL의 country_code 수정/삽입 권한 추가가 필요하며 기존 정책을 해제할 필요는 없음.
- `인증과저장!A11:D11`, `A22:D23`: 가입 트리거와 create_profile() 시그니처/실행 권한 일치.
  함수 본문과 트리거의 전체 SQL은 제공되지 않았으므로 기존 함수를 교체하지 않는 방식으로 보완.
  별도 프로필 BEFORE INSERT 트리거에서 해당 Auth 사용자의 가입 국가만 읽어 저장.

현재 자료와 준비된 변경 사이에 테이블명·컬럼·RLS 명칭 충돌은 발견되지 않았습니다.
기존 가입 함수/트리거를 유지한 상태로 국가 기능을 추가하도록 SQL을 정리했습니다.
남은 단계는 마이그레이션 실제 실행과 DB 기반 계정/게시글 검사입니다.

## 구현한 동작

- 첫 방문은 로그인 없이 홈을 표시. 우측 상단 로그인 버튼으로 이동하며 회원 전용 경로만 로그인 요구.
- 비로그인 사용자의 언어 설정도 로그인으로 강제 이동하지 않고 기존 화면/홈으로 복귀.
- 회원가입에 국가명 선택 추가. 기본값은 대한민국(KR), ISO 국가/지역 코드 249개 사용.
- 국가명은 화면 언어에 맞춰 표시하고 저장값/배지는 대문자 두 자리 코드로 통일.
- 마이페이지 닉네임, 설정의 아이디, 게시글·댓글 작성자 앞에 작은 국가 코드 배지 표시.
- 프로필 편집에서 본인 국가 변경. 화면 언어는 자동 변경하지 않음.
- 로그인 회원의 국가와 같은 게시글을 먼저 표시. 각 그룹 안에서는 인기/최신/분류 정렬 유지.
- 비로그인 회원에게 나의 활동 메뉴를 숨기고 활동 화면 직접 접근 시 로그인 화면 표시.

초기 마이그레이션에서 KR로 저장된 기존 값은 유지합니다. 이번 댓글 추가 작업은 기존 행을 갱신하지 않습니다.
회원 국가 변경 후 예전 글·댓글의 분류와 배지는 작성 당시 국가를 유지합니다.
국가 미선택(누락·NULL·빈 문자열·공백)은 서버에서 KR을 사용합니다. 프로필 저장에서 국가 필드 자체를 생략한 기존 요청은 현재 국가를 유지합니다.
새 댓글 DB 트리거도 프로필 국가가 NULL/공백이면 KR을 저장합니다. 기존 댓글의 NULL은 채우지 않으며, 프로필 자체 누락·인증·권한 오류는 계속 차단합니다.
국가는 선호/소속을 직접 선택하는 값이며 IP나 화면 언어로 추정하지 않습니다.

## DB 적용 전 남은 확인

### 댓글 국가 추가 변경의 복구

- 전체 SQL은 BEGIN/COMMIT 트랜잭션이므로 중간 오류 시 커밋되지 않습니다. 오류 후 같은 세션에 트랜잭션이 남으면 ROLLBACK을 실행합니다.
- 적용 성공 뒤에는 ROLLBACK으로 취소할 수 없습니다. 이전 웹 코드로 복귀한 후 아래 쿼리로 새 댓글 트리거만 제거하면 기존 동작으로 복귀할 수 있습니다.
- country_code 컬럼/값/제약/권한은 유지하여 적용 후 새 댓글의 국가 정보를 잃지 않도록 합니다. 엄밀한 스키마 원상복구와는 다릅니다.
- 적용 전에 동일 이름의 트리거/함수가 이미 있었다면 제거 쿼리를 사용하지 말고 기존 정의로 복원해야 합니다.

```sql
begin;
drop trigger if exists ieb_comment_country on public.ieb_comments;
notify pgrst, 'reload schema';
commit;
```

이 복구는 댓글 국가 추가 변경에만 해당하며 이전 회원 국가 마이그레이션은 되돌리지 않습니다.

1. 제공된 조회본 이후 구조 변경이 없는지 확인. 기존 create_profile()/가입 트리거는 교체하지 않음.
2. 엑셀에서 확인한 본인 수정/본인 글 작성 정책과 컬럼 권한을 유지한 채 필요한 국가 권한만 추가.
3. `supabase/migrations/20261105_member_country.sql`을 실제 구조에 맞춰 검토한 뒤 적용.
   신규 DB도 기본 `supabase/schema.sql` 이후 이 마이그레이션이 필요합니다.
4. 기존 테스트 계정 country_code=KR, 신규 JP 가입/재로그인, KR→JP 변경, 글 작성 국가,
   타인 프로필 변경 차단을 실제 DB에서 확인한 뒤 코드 배포/PR 진행.

마이그레이션은 국가 컬럼/허용값 제약/권한/피드 인덱스와 별도 프로필 삽입 트리거를 추가합니다.
기존 가입 함수가 프로필을 만들 때 Auth 가입 메타데이터에서 국가를 가져오며, 기존 가입 로직은 유지합니다.
게시글 삽입 트리거는 클라이언트가 보낸 국가를 작성자의 프로필 국가로 덮어씁니다.
기존 RLS를 해제하거나 서비스 비밀 키를 브라우저에 전달하지 않습니다.

**아직 SQL은 실제 PostgreSQL/Supabase에서 실행·검증하지 않았습니다.** DB 적용 전에는 새 서버의
bootstrap 쿼리나 가입/국가 저장을 운영에서 사용하면 안 됩니다. 가입은 국가 컬럼 확인 후에만
계정을 생성하여 마이그레이션 미적용 상태에서 선택값이 조용히 유실되지 않게 합니다.
