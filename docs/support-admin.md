# 고객지원 콘텐츠 관리

관리자 페이지의 **공지사항**, **자주 묻는 질문**, **고객지원 · 문의** 탭에서 사용자 페이지의 내용을 관리합니다.

## 관리 가능한 내용

- 공지사항: 제목·본문·공지 날짜·표시 순서·공개 여부, 새 공지 추가 및 삭제.
- FAQ: 질문·답변·표시 순서·공개 여부, 새 질문 추가 및 삭제.
- 고객지원 · 문의: 마이페이지 지원 묶음 이름, 세 메뉴의 이름, 각 페이지 제목, 문의 안내 문구, 문의 이메일.
- 한국어·영어·중국어·일본어 문구를 각각 편집합니다. 한국어는 필수이며 다른 언어는 모든 입력을 비워두면 한국어로 표시합니다. 자동 번역은 하지 않습니다.
- 저장한 내용은 DB에 반영됩니다. 사용자 페이지에서 새로고침하면 최신 데이터를 표시합니다. 삭제하거나 모두 비공개로 전환한 공지·FAQ는 예전 예시로 다시 나타나지 않습니다.
- 이메일이 비어 있으면 이메일/복사 버튼을 숨깁니다. 실제 형식의 이메일은 메일 앱 열기와 복사를 지원하며 `.example` 예시 주소는 메일 링크를 만들지 않습니다.

## 데이터와 권한

`public.ieb_support_content`가 notice, faq, settings 세 종류의 데이터를 관리합니다. `translations`에 언어별 문구, `contact_email`에 문의 주소, `published`에 공개 여부를 저장합니다. `updated_at`으로 동시 수정 충돌을 검출합니다.

일반 방문자와 회원은 공개된 항목만 읽을 수 있습니다. 테이블에 대한 직접 추가·수정·삭제 권한은 없습니다. 기존 관리자 검증 API만 서버 secret으로 변경할 수 있으며, 사용자 스스로 바꿀 수 있는 `user_metadata`는 권한 판단에 사용하지 않습니다. 문의 설정은 하나만 존재하고 관리자 화면에서 삭제하거나 비공개로 만들 수 없습니다.

`supabase/support-content.sql`은 새 테이블·RLS·권한·시간 갱신 트리거를 생성하고 기존 공지 2개, FAQ 4개, 문의 설정 1개를 옮깁니다. `ON CONFLICT DO NOTHING`이 이미 편집한 내용을 덮어쓰지 않습니다. seed 원본은 `supabase/support-seed.json`입니다. 기존 계정·음식·식당·게시글은 변경하지 않습니다.

## 검증

- `node tests/support-content.cjs`: 관리자 인증, CSRF, 입력 검증, 공개/비공개, CRUD, 문의 설정 보호, 충돌 처리, 4개 언어의 실제 사용자 화면 렌더링, HTML 이스케이프.
- 실제 DB에서 RLS와 공개 읽기/쓰기 권한을 검증했습니다. 검증용 임시 데이터는 트랜잭션을 롤백하여 남기지 않습니다.
- `ADMIN_PREVIEW_PORT=8784` 환경변수와 `node tests/admin-browser.cjs`로 별도 포트의 가상 데이터를 사용할 수 있습니다. 이 서버는 Supabase로 연결하지 않습니다. 로그인은 테스트용 아이디·비밀번호만 사용합니다.

기존 Vercel/Supabase 환경변수를 사용하므로 추가 키는 필요하지 않습니다. 코드 배포 전까지 운영 페이지는 기존 내용을 표시합니다.
